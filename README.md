Пять лабораторных работ, которые складываются в одну систему синтеза речи для русского

```

```

## Как устроен практикум

**Работы связаны строго.** Лабораторная N принимает то, что вы сдали на работе N−1. Если
работа не сдана вовремя, выдаётся эталонный артефакт, и факт его использования
фиксируется автоматически в протоколе запуска. Отставание на одной работе не блокирует
семестр, но остаётся видимым при оценивании.

**Перед сдачей проверяйте себя сами.** У каждой работы есть скрипт проверки контракта:

```bash
python scripts/check_lab1.py
```

Он не оценивает качество — он проверяет, что ваш результат вообще пригоден на вход
следующей работе. Красный результат означает, что работа 2 у вас не запустится.

**Что сдаётся.** Архив: код, полученные артефакты (метаданные, модели — но не аудио),
отчёт и протокол запуска. Аудиофайлы остаются на диске, в архив идут их контрольные суммы.

## Установка

Порядок важен. Сначала PyTorch, потом всё остальное.

**1. Окружение**

```bash
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
```

**2. PyTorch — строго из индекса cu121**

```bash
pip install torch==2.5.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cu121
```

**3. Проверьте, что GPU действительно работает — до установки всего остального**

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_capability(0))"
```

Ожидается `2.5.1+cu121 True (6, 1)`. Если видите `False` или ошибку
`no kernel image is available` — остановитесь, дальше ничего работать не будет.

> **Почему именно так.** Начиная с версии 2.8 PyTorch не поддерживает архитектуру Pascal
> (GTX 1080Ti, `sm_61`). Отдельная ловушка: сам coqui указывает индекс `cu128`, а сборки
> под CUDA 12.8 собраны без ядер Pascal — поэтому **нельзя** ставить torch через
> `pip install "coqui-tts[cuda]"`. Ошибка при этом выглядит как проблема с драйвером,
> хотя дело в отсутствующей архитектуре.

**4. Форк coqui с поддержкой многосимвольных фонем**

```bash
pip install "TTS @ git+https://github.com/Arbaletos/coqui-ai-TTS.git@tts-course-itmo-2026-m1"
```

Обычный `coqui-tts` из PyPI не подойдёт: используемый в курсе фонемный набор MFA содержит
символы длиннее одного кодового пункта (`s̪` — это `s` + U+032A), а штатный токенизатор
разбирает строку по одному символу.

**5. Зависимости практикума**

```bash
pip install -r requirements.txt
```

## Данные

Корпус [RUSLAN](https://ruslan-corpus.github.io/) — один диктор-мужчина, 22 200 фраз,
около 31 часа, 22,05 кГц. Скачивается и распаковывается на первой лабораторной.

Готовые выравнивания (TextGrid) и объединённый словарь произношений выдаёт преподаватель:
установка Montreal Forced Aligner требует Docker и в Google Colab невозможна. Пересобрать
выравнивание самостоятельно можно — это необязательное задание в работе 3.

Все внешние ссылки и версии собраны в одном файле: [`configs/sources.yaml`](configs/sources.yaml).

## Оборудование

Кластер университета: Ubuntu 22, CUDA 12.1, GTX 1080Ti. Работы 1–3 считаются на любой
машине, включая Colab. Работа 4 требует GPU и нескольких часов.

## Структура репозитория

```
configs/          канонический аудиотракт, фонемный набор, внешние ссылки
labs/labN_*/
    README.md     постановка задачи и критерии приёмки
    solution/     ← здесь пишете вы
    tests/        тесты, которые вы запускаете сами
    run.py        точка входа, создаёт артефакт
scripts/          проверка контрактов, сборка архива для сдачи
data/             (в .gitignore) сюда качается корпус
artifacts/        (в .gitignore) результаты ваших работ
```

Ваш код живёт только в `labs/*/solution/`. Всё остальное можно обновить, не задев вашу
работу.

## Замечание о выборе архитектуры

FastSpeech2 (2020) — не актуальная промышленная архитектура, и это осознанный выбор. Это
последняя архитектура, в которой конвейер синтеза виден целиком: можно указать пальцем на
длительность конкретной паузы и на позицию ударения. В современных системах на нейросетевых
аудиокодеках всё это существует только в латентном виде.

При этом содержание работ 1–3 устаревшим не является. Современные системы по-прежнему
ошибаются в русских омографах и ударении: неоднозначность `за́мок` / `замо́к` заложена во
входных данных и не устраняется увеличением модели.
